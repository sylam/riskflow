## 1. Background and what we're moving away from

We are computing an optimal dynamic hedge for a daily-fixing Asian (platinum, ~118 fixings) hedged with a small set of CME futures, under a utility objective with a ~10× loss tolerance and no upside hedging. **The horizon for this problem is set by the longest hedge: three fixed-expiry CME futures, the last (October) up to ~9 months out → ~180–190 business days.** (The engine is general to ~255 daily steps; this instance is shorter.) Because the three contracts are the entire tradable universe and the problem ends at the last expiry, the action space is **time-varying and shrinks toward expiry** as contracts settle (§2.5, R9) — not a flat grid. The deal's **last fixing falls before the October expiry** (confirmed), so there is no unhedged post-horizon tail; and since the locked average leaves no price risk after that fixing, the **effective decision horizon is the last-fixing date**: positions unwind to flat there and stay flat to settlement (§2.5). The objective is `AsymmetricUtility_Symlog` (`hedge_solver.py:126–130`): the hedge has no mean to harvest (futures are ~martingales) and its entire value comes from the *concavity* of the utility (Jensen / variance aversion). The simulator (riskflow framework) uses a 3-state hidden-Markov spot model, an AR(1)/mean-reverting basis, and a VAR carry process.

The prior approach (postfix2 through postfix7) framed this as backward LSM-DP: simulate outer paths forward from today, then recurse backward fitting a value-function approximation V̂_t at each step, with a Bellman max over an action grid baked into each fit. Successive iterations fought a series of pathologies:

- **Drain mechanism** in the OLS-basis V̂ (off-hull over-extrapolation of the fitted surface).
- **Off-hull extrapolation** reappearing when V̂ moved to an MLP function class (postfix7).
- **Max-bias compounding** requiring an asymmetric Double-V cross-fit.

The postfix7 smoke (MLP + frozen-inner-MC differential labels, terminal-rollout architecture) produced V_0 = 3.51, exactly pinned to the projection clamp u_max_proj = 3.51, with off-hull query values up to 4.88 (39% above the clamp). Against a hindsight benchmark of ~0.97 this is a structural failure, not a tuning miss. Diagnosis: differential labels constrained the fitted slope on 3 active (position) dimensions, but the MLP had 23 state dims and extrapolated freely along the unconstrained ones; the Bellman max then exploited that freedom on an inner-MC cloud generated by the current fit.

**The reframe.** The postfix2–7 pathologies share a root: a Bellman max applied to a value surface queried on path-coupled, off-hull states generated recursively by the in-progress fit. Huge–Savine differential ML, by contrast, is validated for fitting *smooth payoff functionals with autograd-available differentials over a sampled state distribution*. The design below casts each per-timestep object as exactly that — a supervised fit on a controlled domain — while keeping the dynamic-control max as a separate, explicit operator applied only to the already-fitted surface, never recursively to an in-progress one. This is still backward dynamic programming, and the links are bootstrapped, not independent (see R2); the gain is that each link is now a *solved* problem class, with the destabilising max removed from inside the fit.

## 2. The proposed architecture

### 2.1 Two objects: a fitted continuation function and an explicit decision operator

We **do not** eliminate the Bellman decision operator. We move it out of the regression target.

**Post-decision state** (the argument of the fitted function), after inventory q_t has been chosen for the interval [t, t+1]:

```
post_t = (market_t, q_t, cash_t, partial_avg_t, n_fixings_remaining_t)
```

**Fitted object — post-decision continuation function** C_t(post_t): the value of having already chosen inventory q_t, then continuing optimally from t+1 onward. This is what the MLP fits, with value + differential labels.

**Decision operator** D_t — *not fitted*, applied explicitly:

```
D_t(market_t, q_prev, cash_t, partial_avg_t) =
    max over q_t of  C_t(market_t, q_t, cash_t - cost(q_t - q_prev), partial_avg_t)
```

The max over hedge inventory lives here, in a low-dimensional explicit operator over the already-fitted smooth C_t — never baked into the regression target, never applied to an in-progress fit.

**`market_t` must be the observable belief, not the privileged true state (R1b).** The spot follows a hidden 3-state regime: the regime determines the per-step drift/vol/mean (`stochasticprocess.py:1982–1988`) but is not revealed by the observed price. The codebase exposes the *true* regime one-hot to the critic (`calculation.py:2110–2113`), which is correct for the existing asymmetric actor–critic but wrong here, because `D_t = max_q C_t` is the decision rule and the true regime is unavailable at decision time. So `market_t` carries the **filtered regime belief** `P(regime_t | prices_{0..t})` (a point on the 3-simplex), computed by a forward filter along each path. The true regime is still used — but only to *simulate* the one-step target, never as a `C_t` input coordinate. Note the value is nonlinear (convex) in the belief, so a `C_t` trained on one-hot vertices and evaluated at an interior belief is biased; the belief must be the training coordinate.

State is Markov by construction: the conditional distribution of remaining payoff depends only on the state (belief + liability scalar + cash + inventory), not the path that produced it. We deliberately do not bake forward-consistency between partial_avg and market history into the training set — that independence is what makes each per-t fit self-contained.

### 2.2 The per-timestep fit (post-decision recursion)

The target for C_t is a **λ-return** — a bias/variance interpolation between the one-step bootstrap and a frozen-policy Monte-Carlo rollout (the TD(λ) dial):

```
C_t(post_t)  =  E[ G_t | post_t ],   G_t = y_boot + λ·(y_roll − y_boot)
  y_boot = D_{t+1}(state_{t+1})                          # 1-step bootstrap (low variance, max-bias)
  y_roll = U_T(realized cash + hedge P&L + liability),   # MC return under the *frozen* future
           continuing the SAME inner path to T_dec (the last-fixing date; §2.5), choosing q_u = argmax_q C_u(post_u(q))
```

λ=0 recovers the pure one-step design; λ=1 is a pure terminal rollout (unbiased for the frozen policy, higher variance); 0<λ<1 trades the two. **The toy sets λ** (§8). This is *not* the postfix pathology: the rollout applies the **frozen, already-fitted** future policies on an on-policy path — policy *evaluation*, not a recursive max against an in-progress fit.

**Differential label stays one-step; the rollout supplies value only.** The pathwise differential is `∂y_boot/∂post_t` — one step through C_{t+1}, exactly as before. We deliberately do **not** compute `∂y_roll/∂post_t`: that would differentiate through the full 255-step dynamics chain (regime/basis/VAR/spot), reopening the full-rollout autograd graph the one-step design exists to avoid (the `no_grad` inner-MC boundary, calculation.py:2281) — affordable only with checkpointing and a rewrite of the compute story. The value-only rollout instead **reuses the existing `no_grad` inner-MC machinery** (the `no_grad` boundary is a feature here). Value and gradient labels then disagree only by O(δ) (below), which is precisely the quantity we monitor — a large disagreement is a signal to fix C_{t+1}, not a reason to pay for rollout gradients. Truncated n-step rollout gradients are a Tier-3 escalation only if δ shows structured error the bootstrap gradient can't capture.

**The residual `δ_t = y_roll − y_boot` is the core compounding diagnostic.** Computed under **common random numbers** (boot and roll share the same inner path), δ isolates fitting error from MC noise: `E[δ_t | post_{t+1}] = V^π_{t+1} − C_{t+1}`, and it is read **scale-normalized** — `δ_norm = (y_roll − y_boot) / max(std(y_roll), floor)` — so the diagnostic flags *structured normalized* residual rather than just large raw residual (utility, remaining-risk, and cash scales all change with t). i.e. C_{t+1}'s error as a fit to the frozen policy's value, localized by timestep and state region. Flat, structureless δ ≈ the one-step stack is sound; δ that depends on cash, inventory, belief, partial-average, or action-boundary proximity is the "stacking 255 times" failure made visible — and the correction signal (raise λ, or add rollout/boundary rows there). This audits *value fidelity*; whether the *improved* policy `D = max C` is good is the separate question the policy-evaluation metric (§8) answers — the two are complementary.

**Fit the advantage, not the absolute value.** Decompose `C_t(post_t) = B_t(post_t) + A_t(post_t)`, where `B_t` is an *exact, analytic* baseline (liability PV + exact cash/hedge accounting for a reference action — no-trade or the static delta hedge) and the MLP learns only the residual premium `A_t`. The baseline must be exact, or its noise re-enters; the good baselines are all closed-form given the deal engine. This shrinks what the net learns to a small, smooth quantity. **The decision operator always maximizes the reconstructed `B_t + A_t`** — `B_t` is action-dependent (cash cost, hedge P&L, inventory carry all move with q), so it cannot be dropped from the ranking. In pairwise form the operator ranks `[B_t(post(q)) − B_t(post(q_ref))] + [A_t(post(q)) − A_t(post(q_ref))]`: the residual difference comes from the MLP, the baseline difference is computed analytically. Only `A_t` is learned; both differences are ranked. The `_fit_ols` path already fits an MLP on an OLS residual (`hedge_solver.py:415`); here the baseline is the exact economic one and the residual carries the differential labels.

**Belief-target integration (R1b).** When `market_t` carries a filtered belief, the continuation target must integrate over the latent regime *conditional on that belief*: `C_t(b_t,…) = Σ_r b_t[r]·E[D_{t+1} | regime_t = r, …]`. This splits by how the belief was sampled. **Forward-path beliefs** (the §2.3 default — whole market vectors drawn from forward sim) ride with their own true regime, and that `(belief, true-regime)` pair is a correct joint draw, so you simulate forward from the path's true regime and the regression integrates over the latent regime automatically — no enumeration. **Synthetic / off-path beliefs** have no legitimate regime attached and must draw `r ~ b_t` (or enumerate the three regimes weighted by `b_t`) for the inner-branch simulation. The rule for the implementation: keep beliefs riding with their forward paths; never pair a privileged true regime with a belief that did not come from that path.

Terminal:

```
D_T(state, q_prev, cash) = terminal utility at the last-fixing date T_fix:
                            average is locked -> liability is a known cashflow,
                            all live positions unwind to flat (realize P&L),
                            utility on the resulting wealth
```

Backward, for t = T-1 ... 0:

1. **Sample N ≈ 16k–32k post-decision states** post_t = (market_t, q_t, cash_after_trade, partial_avg_t) from designer boxes (Section 2.3). The market/inventory/cash/partial_avg *blocks* are drawn independently (see R4); within the market block, whole market_t vectors are drawn from the forward-sim marginal so cross-factor correlation is preserved (see R3/§2.3).
2. **Simulate the inner step(s)** post_t -> {state_{t+1}^(j)}, j = 1...M, with M tiny (M=1, or M=2 antithetic, up to 4) — *not* a fat fan. Coverage and variance reduction come from the **fat outer batch** (≥16k examples) plus the regression averaging and the differential labels, exactly as in Huge–Savine.
3. **Apply the decision operator at t+1 and average** to build the regression target:
   ```
   y_boot = D_{t+1}(state_{t+1}^(j))                          # one-step bootstrap
   y_roll = terminal utility at T_dec under the frozen future policies D_u
   value label        = mean_j [ y_boot + λ·(y_roll − y_boot) ]   # λ-return
   differential label = mean_j  d y_boot / d post_t               # one-step ONLY (no d y_roll)
   ```
   where D_{t+1}(s) = max over q_{t+1} of C_{t+1}(market_{t+1}, q_{t+1}, cash_{t+1} - cost(q_{t+1} - q_t), partial_avg_{t+1}). The max is `11^(live contracts at t+1)` forward passes through the already-fitted C_{t+1} MLP per branch — 1331 only while all three are live, 121 then 11 after each expiry — no new simulation.
   **The structure is fat-outer / tiny-inner, not nested.** This is the canonical Huge–Savine LSM regime: each of ≥16k outer examples carries a single noisy conditional label (M=1), and the regression *is* the conditional-expectation estimator — the averaging happens across examples, not within a per-row fan. Savine's results (basket at 1k examples, autocallable and the real netting set at 8k) are all single-path. The variance reduction comes from three places, **none of them nesting**: the fat outer batch + regression averaging; the differential labels (Huge–Savine's free lunch — nm differentials from m examples); and antithetic pairing at M=2 (what Savine's demo notebooks actually used). A small M=4 is the ceiling, justified only if the *maxed*/λ-return label's single-sample differential proves noisier than a smooth payoff (the R7 kink). The toy picks M (§8). **Note:** M does not touch the upward max *bias* (R2) — that is the job of the λ-return / LCB / Double-V operator, never of inner fan-out.
4. **Compute differentials** dC_t/d(post_t) via autograd. By the envelope theorem, the gradient of D_{t+1} at its optimum is ∂C_{t+1}/∂(state) evaluated at the maximizing q*, with the dq*/d(state) term vanishing at the optimum — implement by detaching q* and differentiating C_{t+1} there. So the discrete argmax does not corrupt the differential labels. The one-step simulation is differentiated through directly (single step, so the no_grad terminal-rollout boundary at calculation.py:2281 does not apply).
5. **Fit C_t** on (post_t, value, differential) with the postfix7 joint value+derivative loss.

### 2.3 Designer boxes — where samples come from

- **Market box:** the forward-sim marginal distribution of market_t, generated from *today's* market as the t=0 start. We run an initial 16k–32k outer forward sim to T to characterize this. Sampling draws **whole market_t vectors** (spot/regime-posterior, basis level, carry factors together), not each factor from its own marginal — the cross-factor correlation is part of the reachable distribution and sampling factors independently would manufacture unreachable joint states. V̂ is *today-specific*, refreshed daily, so it only needs to cover the region reachable from today's market (Section 4).
- **Cash box:** uniform on a loss-tolerance-scaled band around the liability reference. **Reparameterize cash** to `loss_budget_remaining = (cash − liability_ref_t) / (loss_tolerance · loss_scale_t)`, where `loss_scale_t = max(|unhedged_liability_PV_t|, floor_scale)` is an explicitly **positive** scale — commodity swap PVs are signed (payer/receiver, strike vs forward), so dividing by a raw, possibly near-zero or negative liability is a bug. Sample/clamp `loss_budget_remaining` over a bounded range. The symlog objective is not translation-invariant (`hedge_solver.py:126–130`), so cash is a genuine, level-dependent coordinate and cannot be collapsed; the normalized form keeps the axis bounded and economically meaningful, and lets us enforce a **monotonicity guard** (more cash never lowers C_t) that the max would otherwise eventually exploit.
- **partial_avg box:** drawn over the plausible accumulated-average range given that t fixings have occurred.
- **inventory q_t:** **sampled, not gridded** as a fit-time state coordinate (one inventory per state row). The smooth-payoff differential information carries the position-direction sensitivity of C_t. The dense 1331 grid appears only inside the decision operator D (Section 5).

The market/cash/partial_avg blocks are sampled independently of each other; the one-step transition couples them, and the query manifold sits inside the product training box (R4).

**Three training-row sources per C_t.** (1) **Designer-box rows** — the broad coverage above, with sampled q_t spanning the action range (needed because the argmax queries C_t at all candidate q). (2) **On-policy anchor rows** — states visited by the frozen future policy along the y_roll rollouts (§2.2), carrying high-quality terminal-grounded *value* labels; a single forward rollout yields anchors for *every* timestep it passes through, harvested cheaply (O(N·T)) and added as extra data, *not* a replacement for designer-box coverage (they only visit the chosen q, not all candidates). **These rows enter the value loss only (differential weight 0)** — they have no cheap consistent gradient (a true one would be the rollout gradient we avoid), so the differential term is carried entirely by the designer-box rows, where the one-step bootstrap gradient is clean. (This is the conservative default; promoting anchors to also carry the one-step bootstrap gradient is a later option if needed.) (3) **Boundary rows** — states where δ_t is large or the top-two actions are close, resampled with higher M / more rollouts (this is the Tier-3 active-resampling refinement, §9, turned on only if δ shows structure there).

### 2.4 The deal supplies the Markov-correct liability transition (not the whole value operator)

We do **not** build a value operator. But we are careful about what the deal does and does not supply.

The deal supplies the **Markov-correct liability state transition / residual payoff** under known past fixings. Verified against `pv_energy_cashflows` (`pricing.py:2600`): past fixings are carried as per-reset **known values** (`known_resets`, `2607–2636`) — *not* a scalar `Realized_Average` field on the energy-cashflow path — and the payoff is a weighted sum over `[known ++ simulated]` resets, `Σ weight × reset` via `RESET_INDEX_Weight` (`2696`), then `Nominal × (Start_Mult × payoff + FloatMargin)` (`2702–2704`). The sum is linear in the resets, so for the average-rate **swap** there is no kink and the residual transition is exact.

Two consequences:
- **The sufficient liability state is a single scalar** — the accumulated weighted sum of past fixings (equivalently, weighted partial-average × cumulative weight). This refines the earlier `(partial_avg, n_remaining)`: with general per-fixing weights it is the weighted partial sum, and `n_remaining` is a function of t.
- **To realize a sampled liability state at fit time**, set the aggregate of `known_resets` to the sampled weighted sum — only that sum enters the payoff (`2696–2698`), so any decomposition with the right total is equivalent. No new scalar field is needed; the `Realized_Average`-style injection the doc originally assumed is replaced by driving the known-reset aggregate.

(Earlier framing kept for reference: `FixedEnergyDeal` carries a scalar `Realized_Average` (instruments.py:5001) and FRAs use `Use_Known_Rate`/`Known_Rate` (4753–4757). The energy-cashflow path read here uses the per-reset known-value mechanism, which is the one that matters for the average-rate swap.)

The **value operator is more than this.** The DP objective is expected utility of `cash + hedge P&L + liability payoff`. The deal supplies only the liability component. The full target is assembled from:

```
one-step conditional expectation  +  cash/inventory/hedge-P&L accounting  +  D_{t+1} (= max_q C_{t+1})
```

The deal gives us the hardest piece (the Markov-correct residual-liability transition) for free; the cash/hedge accounting and the continuation max are ours.

### 2.5 When the decision operator is applied

The action grid is queried via D_t = max_q C_t **whenever a decision is required**. Its size is **time-varying**: `11^(live contracts at t)` — 11³ = 1331 while all three futures are live, 11² = 121 after the first expiry, 11 over the final stretch — and at each expiry the settling leg's position is cash-settled (added to realized P&L) and the inventory coordinate collapses (3-vector → 2-vector → scalar). The live-contract set is a deterministic function of t. **The decision horizon ends at the last fixing — write `T_dec = T_fix` (last-fixing date) and `T_pay` for the later deterministic settlement/payment date.** Once the average is locked at T_dec there is no price risk to hedge, so a hard constraint forces `q = 0` for all t ≥ T_dec (this is also what the variance-averse objective wants on its own, since a naked position in a martingale future only adds variance; the constraint removes a region where fit error could let the argmax take a naked bet). The window `[T_dec, T_pay]` is a deterministic flat carry to settlement, not a decision — the rollout `y_roll` terminates at `T_dec` (known liability + forced unwind, plus deterministic carry if needed), never at the October expiry. Decisions are required:

- **during backward target construction** — D_{t+1} builds the regression target for C_t (Section 2.2 step 3);
- **at t=0** — D_0 produces today's hedge from today's observed state;
- **in production, each day** — D_t on the refreshed observed state.

This is the correction from v1. The dynamic hedge requires re-optimizing inventory at every step; applying the argmax only once at t=0 would value a single static hold and is wrong.

## 3. Why this sidesteps the postfix2–7 pathologies

- **Off-hull exposure is made observable and controllable** *(softened from v2's "no off-hull by construction," which overclaimed and conflicted with R3)*. Each C_t is queried mostly at states inside its own designer box; the next-step transition is intended to land inside C_{t+1}'s box because the boxes cover the reachable region with margin, and the existing hull-clamp handles small leakage. But off-box queries are still possible — cash after hedge P&L can leave the cash box, extreme inventory choices can push the next state out, the clamp can *mask* a failure rather than fix it (R3). So the implementation instruments every timestep:
  - % of D_{t+1} queries outside C_{t+1}'s training box;
  - % clamped by the hull clamp, and distance-to-boundary statistics;
  - cash-box breaches and inventory-bound hits (frequent bound hits ⇒ grid too narrow or the model is being exploited);
  - the **optimism gap** `max_q C_A(q) - C_B(argmax_q C_A)` (see §7-R2) — a large gap means the hard max is feeding on fit noise.
- **The max is over a controlled domain, not an in-progress fit.** This is the key difference from postfix7. There, the Bellman max ran over V̂_{t+1} queried on an inner-MC cloud generated by the current fit, on off-hull, path-coupled states. Here the max runs over the *already-fitted, frozen* C_{t+1} at *designer-sampled* states. The pathology that let the max exploit unconstrained extrapolation directions is removed because there are far fewer off-hull directions to exploit, and what leakage remains is measured rather than hidden.
- **No basis-class misspecification drain.** Each fit is an MLP on a bounded sampled domain — the published differential-ML regime — not an OLS polynomial extrapolating off-support.
- **Max-bias is reduced, not eliminated.** Because the recursion solves the dynamic problem, the max stays in the control loop and its bias still propagates: each C_t target depends on D_{t+1} = max_q C_{t+1}, and the max of a noisy estimate is upward-biased. The honest statement: the max is moved out of the fitted function and applied as a small explicit operator on a controlled domain, which is far less pathological than postfix7's recursive in-fit max — but it is not zero, and it compounds over the horizon — up to 255 links (R2). The mitigations are pre-identified (§7-R2/R7): the baseline is the hard max; double/ensemble and soft/annealed operators are staged and tested on the reduced problem, deployed only if the bias compounds.

## 4. Key design decisions and their justifications

| Decision | Choice | Justification | Risk if wrong |
|---|---|---|---|
| V̂ scope | Today-specific, daily refresh | Only need coverage reachable from today | If intraday market moves materially, surface is stale before refresh |
| Market box | Forward-sim marginal of market_t from today, sampled as whole vectors | The reachable distribution at t is what forward-sim from today produces; cross-factor correlation is part of it | If marginal is narrower than the policy-relevant region (mean-reverting factors, short horizon), coverage gaps |
| Cash box | `loss_budget_remaining` over a bounded band, positive `loss_scale` | Loss tolerance bounds reachable cash; signed-PV-safe normalization (§2.3) | If optimal policy visits cash outside the band, off-domain queries |
| Inventory at fit | Sampled, not gridded (state coord) | Smooth-payoff differentials carry position sensitivity | If C surface is sharp in inventory directions, sampling under-covers |
| Inventory in D | Dense grid (decision operator) | Argmax needs candidate coverage to find the optimum | Coarse grid -> suboptimal policy and kinked targets (R7) |
| MC structure | Fat outer (≥16k) × tiny inner (M=1, or 2 antithetic, ≤4) | Canonical Huge–Savine LSM: regression averages across examples; differential labels reduce variance; Savine used single-path | If M=1 differential labels of the maxed/λ-return target are too noisy, bump to 2–4 antithetic — never a fat fan |
| Decision operator | LCB-pessimistic family selects, β set on toy (β=0 = hard max); Double-V audits | LCB penalizes ensemble uncertainty; the decoupled Double-V evaluation measures residual optimism | Naked hard max over up to 255 links may compound optimism (R2/R7) |
| Liability transition | Existing deal pricing + known-reset weighted aggregate | Markov-correct residual-payoff verified on `pv_energy_cashflows` (R6) | Drive via the `known_resets` aggregate; basis/FX reset composition still to confirm for the live config |

## 5. Compute and hardware

Target: RTX 3090 (24 GB), daily refresh. **Provisional — depends on the sampled-not-gridded inventory decision at fit time holding (Section 2.3) and on M staying modest (Section 2.2).**

Working set per t: ~16k post-decision state rows × M inner (1–4, antithetic) ≈ 16k–64k path-steps; at fp32 over ~23–30 deep dims, comfortably under 1 GB — `B_inner` is a free parameter (`calculation.py:2229`) and a 16k outer batch with M≈2 runs in a single chunk under the 32k flat-memory cap (`2250`). The MLP fit (≈1.6k params, 100 epochs, 16k batch) is trivial. (This is ~100× less inner work than the nested-fan figure earlier drafts carried, so the outer batch can be made fatter for coverage rather than spending paths on a per-row fan.)

The decision-operator max costs `11^(live contracts)` forward passes through the frozen C_{t+1} MLP per branch — 1331 only over the early window where all three futures are live, 121 then 11 thereafter — no new simulation, no autograd graph beyond the detached-q* envelope evaluation. On a 3090 this is cheap relative to the inner-MC step and deal pricing. A double-estimator mitigation doubles MLP forward passes; the MLP is not the bottleneck, so this stays affordable.

Per-t wall-clock estimate: ~30–60 s (inner-MC step + deal pricing dominant). At the 255-fixing design horizon -> ~2–4 hours; the 118-step deal -> ~1–2 hours. Both fit an overnight daily refresh. The ensemble operator (K× MLP forward passes) and the near-terminal high-fidelity solver (a bounded one-time high-M/exact-unwind solve over the last K days) add little — the MLP is not the bottleneck and the oracle touches only K of the steps.

**Rollout-target cost.** Harvesting on-policy anchor rows from full forward rollouts is O(N·T) — one forward pass yields a label at every t — same order as the one-step design, and value-only so it runs under `no_grad`. The expensive variant is a *paired* rollout from every designer-sampled state (O(N·T²)); that is reserved for a diagnostic *subsample* (the δ curve) and boundary rows, not run on all rows, so it does not move the budget. Rollout gradients are not computed (§2.2), so no full-rollout autograd graph is ever built.

**What would force A100s:** (a) gridding inventory as a fit-time state coordinate (the cross-product 16k × 1331 ≈ 21M rows is intractable on 24 GB); (b) the outer batch needing to grow far past 16k for coverage at large t. Inner fan-out is *not* a scaling axis — it stays at 1–4. Neither (a) nor (b) is baseline.

## 6. Engineering scope (bounded; no research risk in any single step)

1. **Regime belief filter (new — gates R1b).** Add a forward HMM filter producing `P(regime_t | prices_{0..t})` along each path, and make it the spot's `market_t` coordinate in place of the privileged true-regime one-hot (`calculation.py:2110–2113`). The true regime stays available for *simulating* the one-step target. Bounded (a standard forward recursion over the existing transition matrices), but it is genuinely new and load-bearing — do it before anything else.
2. **Liability-state injection via known-reset aggregate.** Drive the sampled accumulated weighted sum by setting the `known_resets` aggregate consumed at `pv_energy_cashflows` (`pricing.py:2607–2636/2696`). This replaces the originally-planned scalar `Realized_Average` injection; the energy-cashflow path uses per-reset known values, so only their weighted sum needs to match.
3. **Arbitrary-state restart (Gate 0 — substantially confirmed by inspection).** The one-step fork from a designer-sampled state is an inner-MC-style fork, and inner mode already accepts per-path batched initial state for every process: HMM (`log_spot0`/`regime0_inner`), CSForward (`initial_curve` with a B dim, `stochasticprocess.py:964–969/1015–1020`), VAR (`X_0` solved per-path from `curve_0`, grad-preserving, with a late-fork ridge fallback, `2537/2549/2542–2560`), basis (`(B,)` initial-basis vector, `2771–2772`). Residuals to close in Gate 0 (§8): run the one-step *differentiable*-fork smoke (the existing inner-MC `no_grad` is the old terminal-rollout's choice and does not apply to the new one-step sim); sample the spot/regime/basis block **jointly** (the basis reads the linked spot+regime, `2787–2788`); and note the VAR `X_0` exact solve requires a **3-knot** contract ladder (`2520–2529`) — a larger hedge set needs the lstsq path.
4. **Bounds collection.** From the initial forward sim, collect per-t liability_t (hence the cash box). Lightweight.
5. **Decision operator D_t — largely already present.** `build_action_grid` + `search_action_grid` (`hedge_solver.py:41/59`) already implement the hard `max_q C_t` over a discrete contract-unit grid. What is new and small: the envelope-theorem differential (detached q*) for the target gradient, and the double/soft operator variants — built to swap without touching the fit loop.
6. **Per-t fit loop.** Reuse `ValueFunctionApproximator`'s `mlp_differential` dispatch (twin-net joint value+derivative loss per Huge–Savine §1.2.1, `_compute_target_gradients`, standardization, hull clamp, C¹ activation — all present, `hedge_solver.py:263+`). Drop the terminal-rollout / cross-fit scaffolding. Net code change is modest.
7. **Time-varying action grid + expiry settlement (R9 — resolved as fixed-expiry).** Three fixed-expiry contracts, no roll into successors. Make `build_action_grid` emit `11^(live contracts at t)` (deterministic from the expiry calendar), carry the per-contract inventory vector in the post-decision state, and at each expiry boundary cash-settle the expiring leg (realized P&L → cash) and drop its inventory coordinate. No roll/calendar-spread cost layer is needed (nothing to roll into); the existing L1 turnover on position changes plus expiry settlement suffices. Bounded and well-defined.

## 7. Risks the reviewer should pressure-test

- **R1a — Forward Markov-sufficiency.** *(Closed by the code read.)* The regime fully determines the spot's per-step drift/vol/mean (`stochasticprocess.py:1982–1988`), so `(spot, regime)` plus the carry factors is the simulator's Markov state, and the privileged extractor exposes the regime. The one-step bootstrap target is therefore well-determined, not underdetermined. The mean-reverting basis/carry factors are low-dimensional and exposed. No residual concern here.
- **R1b — Belief-state / observability.** *(New, and now the single most important pre-build risk.)* The regime the extractor exposes is the **true** latent regime (`calculation.py:2110–2113`, "privileged ... for the critic", `1678`), not a filtered posterior — there is no filter in the codebase. That is correct for the existing asymmetric actor–critic, where a separate observable-state policy makes decisions. This redesign makes `D_t = max_q C_t` the decision rule, so the value function's input must be observable at decision time — and the true regime is not. The fix is to make `market_t` carry the **filtered belief** `P(regime_t | prices_{0..t})` and train `C_t` on it (§2.1, §6). This is not a free re-label: the value is convex in the belief, so a `C_t` trained on one-hot vertices and queried at an interior belief is biased. If the belief-filter route fails (e.g. the belief is too diffuse to discriminate, so `C_t` is nearly flat in it and the hedge loses the regime signal), the redesign's central premise — a per-step decision from an observable state — is in question. **Check via the empirical same-full-observable-state / different-history test, plus a filter-calibration check (§8).**
- **R2 — Error + max-bias compounding over the horizon (design target 255 links).** Each C_t target depends on D_{t+1} = max_q C_{t+1}, itself built on an imperfect fit, recursively to T. Two error sources stack: function-approximation error (variance, reduced by M and by differential labels) and upward max-bias (systematic, *not* reduced by M). Differential ML degrades gracefully in the paper, but the paper does not stack 255 fits *with a max at each link*. This is the central research risk — and the **advantage decomposition (§2.2) plus policy-evaluation (§8) reframe it**: what must survive depth is the action *ranking*, not the value *level*, since the deployed object is the argmax. The **λ-return target (§2.2) is the primary lever**: raising λ replaces trusted fitted future values with realized terminal utility under the frozen policy, removing the bootstrap/max-bias from the value target (at the cost of variance), and the `δ_t` residual localizes exactly where the stack is drifting. Checkable on the full-depth toy (§8) via the δ curve, action-error-rate, and policy regret, not just value drift. **Operator family, β set on the toy (not asserted):**
  - **Pessimistic / LCB ensemble max** (`q* = argmax_q [mean_k C_k − β·std_k]`), with β=0 recovering the plain max — only take a clever trade when the ensemble agrees. The Double-V decoupling already exists (`hedge_solver.py:1028`); LCB is K heads + the std-penalty rule. **LCB selects, Double-V audits:** LCB is the production selector, but it does *not* subsume the double-estimator — correlated ensemble heads make the estimated std too small, so LCB can stay optimistic; the decoupled-evaluation optimism gap `mean_k C_k − C_{eval}(argmax)` is a separate, necessary audit. β is chosen from the toy depth-curve, not guessed; the reviewer wanted it asserted from day one, but the full-depth toy sets it for free.
  - **Soft / annealed max** (kink fix): smooth operator during *training*, hard/LCB for *production* decisions, anneal the temperature down. Caveat unchanged from v4: a soft target changes what C_t represents (continuation under the smoothed policy), so the anneal schedule is load-bearing.
- **R3 — Designer-box coverage vs. the reachable manifold.** We claim state_{t+1}(post_t) lands inside C_{t+1}'s box. For mean-reverting factors at short horizons the forward-sim marginal may be narrower than where the policy pushes the state, creating off-box queries the hull clamp masks rather than fixes. Instrumented in §3 rather than assumed away.
- **R4 — partial_avg / market independence at fit vs. coupling at query.** Training samples (market, partial_avg) independently; the one-step transition couples them. The query manifold sits inside the product training box, so this should be fine, but warrants a sanity check.
- **R5 — Sampled-not-gridded inventory adequacy at fit.** If the C surface is sharp or non-smooth in inventory directions (e.g. near turnover-cost kinks), sampled inventory may under-cover and differentials may not rescue it. The 3090 compute claim depends on this holding.
- **R6 — Liability-transition semantics.** *(Resolved by the code read.)* `pv_energy_cashflows` (`pricing.py:2600`) carries past fixings as per-reset known values and computes the payoff as a weighted sum over `[known ++ simulated]` resets (`RESET_INDEX_Weight`, `2696`; linear `Nominal × (Start_Mult × payoff + FloatMargin)`, `2702–2704`). For the average-rate **swap** this is exact and kink-free, and the sufficient liability state is a single scalar (the accumulated weighted sum), driven at fit time via the `known_resets` aggregate (§2.4). The scalar `Realized_Average` mechanism originally assumed is not the one on this path, but the residual transition we need is available and verified. *Residual check:* confirm the basis/FX resets (`comm_rates`, `forwardfx` at `2683/2685`) compose with the weight sum as assumed for the platinum book's actual currency/basis config.
- **R7 — Decision-operator kinks degrade the smooth-fit advantage.** A discrete-grid argmax makes D_{t+1} piecewise in state: as state varies, q* jumps between grid points, putting kinks in the regression target. Fitting a smooth MLP C_t to a kinked D_{t+1} target gives back some of the smoothness that motivated differential ML, and per-step fit error concentrates at the kinks — which is what R2 compounds. *(Confirmed by the code read.)* Actions are discrete target inventory in **contract units** on an enumerated grid (`build_action_grid`, `hedge_solver.py:41`), chosen by a hard chunked argmax with no action gradients (`search_action_grid:59`), with L1 turnover kinks (`_turnover_cost:85`). So the action space is genuinely discrete and the v2-corrected mitigation stands: **soft/annealed max smoothing of the target** (§7-R2), not continuous-action relaxation. (Continuous relaxation would only ever be an *optimisation-method* swap inside `search_action_grid` to dodge the 11^H grid cost in the portfolio case — separate from target smoothing.)
- **R8 — Portfolio generalization (book of average-rate swaps, one underlying).** *(Inverted by the code read — this simplifies, not complicates.)* Per-fixing weights are first-class (`RESET_INDEX_Weight`, `pricing.py:2696`) and the swap payoff is linear in the resets (`2702–2704`), so a book of average-rate swaps on a single underlying **collapses to one synthetic weighted swap**: aggregate each future fixing date's weight as `w_d = Σ_legs Nᵢ · weightᵢ`. The fitted `C_t` has the *same* dimensionality as the single-deal case — the liability state stays one scalar (accumulated weighted sum) and does **not** grow with the number of legs; `market_t` is shared (one underlying), so R1a/R1b are unchanged. The cost pressure moves to the **hedge dimension**: a term-structure exposure wants futures of several maturities, and the decision grid is 11^H (`build_action_grid`), so H, not the book size, is what strains the 3090. Two caveats: (i) the collapse is exact only for **linear** legs — each Asian-*option* leg (strike clamp, `2083/1817`) re-introduces its own average as a state coordinate, so confirm the book is all swaps; (ii) **the loss budget is global (one utility on total book wealth) — confirmed.** This is the *coupled* multi-underlying case: the clean one-model-per-underlying decomposition does **not** hold (the right hedge for one underlying depends on the rest of the book via diversification and the shared loss pool), but it does **not** force a joint `1331^N` DP — the coupling is only through scalar total wealth, so the single-underlying solver stays the engine under a coordination layer. **Crucially, portfolio value is the *coupling* coordinate, not a state replacement: the book state remains the union of per-underlying remaining-risk states, because value is sufficient for the objective but blurs the remaining risk the hedge keys off.** The full implementable decomposition (best-response, the role of differential PCA as the book-scale compressor, and the value-as-state anti-pattern) is specified in §9 "Book extension." **This is entirely a book-time concern: the single-deal first build (toy + platinum) is one underlying, where the coupling is vacuous, so it is unaffected.**
- **R9 — Hedge-instrument identity over the horizon** *(self-raised; now resolved as fixed-expiry)*. The hedges are **three fixed-expiry CME futures**, the last (October) at the horizon; they are the whole tradable universe, so there is **no roll into successors** and no calendar-spread cost layer. The consequences are favorable and concrete (§2.5, §6.7): the decision grid is time-varying `11^(live contracts)` (1331 → 121 → 11), each expiry cash-settles its leg and collapses the inventory coordinate, and the terminal boundary is intrinsically tiny (11 actions → forced unwind). What remains a genuine *risk* rather than a resolved mechanic: the max-exploitation surface (R7) and the deepest fit stack (R2) both concentrate in the early window where all 1331 candidates exist — that is where the LCB operator and the δ diagnostic must hold. The tail is benign by construction.

## 8. What would falsify the approach cheaply, before full build

The gates run in this order — each is cheap and gates the next: **Gate 0 (fork smoke) → belief filter + calibration (R1b) → full-depth toy (with the δ residual curve) → advantage-learning on the toy → operator/β and λ sweep → near-terminal high-fidelity solver → real T/T-1/T-2 smoke → only then the full horizon.**

- **Gate 0 — arbitrary-state differentiable-fork smoke.** Code inspection says every process supports per-path batched init in inner mode (§6.3), so this is expected to pass, but it must be *run*, not assumed: build a batch of designer-sampled states, fork **one step with autograd enabled**, and confirm (a) finite, sensible pathwise differentials of the one-step output w.r.t. the sampled state, (b) the VAR `X_0` round-trip guard holds (`stochasticprocess.py:2552`), and (c) the basis/regime/spot block forks consistently when sampled jointly. If any process can't restart from a batched arbitrary observable state under grad, the whole sampled-state architecture stalls — so this is the true first gate.
- **Verify R1 — R1a closed, R1b is the live check.** R1a (forward sufficiency) is settled by the code (`stochasticprocess.py:1982–1988`). For R1b: build the forward belief filter, then (i) **filter-calibration check** — bucket paths by predicted belief and confirm the empirical true-regime frequency in each bucket matches the predicted belief (catches a filter that runs but isn't calibrated); (ii) **same-full-observable-state / different-history test** — condition on *all* observable Markov coordinates (spot, belief, basis, carry, liability weighted sum, loss-budget, inventory, time features), not belief alone, since two histories with the same belief but different basis/carry/spot need not share a next-step distribution; confirm next-step conditional distributions match within noise. The sharper failure to watch for is *degeneracy*: if the belief is so diffuse that `C_t` is nearly flat in it, the hedge loses the regime signal — check that `C_T` and `C_{T-1}` have non-trivial gradient in the belief coordinate on held-out data.
- **Verify R6 — done.** Confirmed: `pv_energy_cashflows` carries past fixings as per-reset known values and sums `weight × reset` over `[known ++ simulated]` (`pricing.py:2696`); exact and kink-free for the swap. Only residual: confirm basis/FX reset composition for the actual currency config (R6 note in §7).
- **Brute-force reduced-problem comparison — run to the full design horizon.** Build a tiny exact case and compute the exact grid DP by brute force, then fit the proposed post-decision C_t surfaces. Give the toy a **staggered-expiry structure** (e.g. two hedge contracts expiring at different times, so the action grid steps 11²→11→unwind), so the time-varying grid, the expiry cash-settlement, and the inventory collapse (R9) are actually exercised rather than assumed — the single-hedge toy only represents the terminal regime. R2/R7 is a *depth-driven* failure by hypothesis: at shallow depth, error that settles, accumulates linearly, or snowballs all look alike, and the two reference points (dynamic DP vs static-hold) sit too close to resolve. The toy is exact-DP-tiny, so rather than test shallow and extrapolate, run the actual horizon:
  - **Run the toy to full depth, and log the policy-evaluated value as the primary read.** The toy is an exact grid DP on a tiny state space, so depth is free — run it to the **full design horizon (255)** at 30/60/118/180/255, no extrapolation. Plot, at each depth: exact-DP value, fitted D_0, **policy-evaluated value** (the learned argmax policy rolled forward under fresh MC), static-hold value, optimism gap, and **action-error rate** vs the exact policy. The verdict metric is the *policy-evaluated* curve and the action-error rate, not fitted D_0 — D_0 may drift while the policy still ranks actions correctly and ships.
  - Compare against the **exact dynamic grid-DP** (a match here confirms the architecture) **and** the **static-hold value** (a match *here instead* means the recursion collapsed to passive-hold — the v1 failure mode). The gap between these two references widens with depth, which is the other reason to run deep.
  - **Use the toy to choose M, the operator, β, and λ.** Run M=1 (single-path) vs. M=2 antithetic vs. M=4; hard vs. LCB-pessimistic (sweep β) vs. soft max; and λ from 0 (pure bootstrap) to 1 (pure rollout), against the exact DP across depth. Pick the smallest M and the simplest operator/β/λ that keep action-error-rate flat in depth. Consider *deliberately undersizing* the MLP so per-link error is large enough to make the compounding regime observable rather than buried under the noise floor.
  - **Plot the scale-normalized `δ_norm` residual (under common random numbers) across depth, state buckets, and action-boundary proximity** (§2.2). This is the primary compounding microscope: flat structureless δ ⇒ the one-step stack is sound and λ can stay near 0; δ that varies with cash/inventory/belief/partial-average ⇒ localized fitted-value drift — raise λ (or add rollout/boundary rows there) and check whether the action-error curve flattens.
- **Near-terminal high-fidelity solver (build step, not just a test).** For the last K≈10–30 days, replace the learned C with a high-fidelity local solve — *exact* in the reduced grid toy, *high-M / exact-unwind / brute-force-grid* in the real continuous-state problem (where stochastic market/belief/cash/inventory rule out a literal exact solve) — and train `C_{T-K}` against that clean boundary. The terminal is where the backward stack's noise originates and where the state is simplest to solve exactly, so a clean anchor there reduces error injected into all earlier links.
- **Single-step / two-step smoke on the real problem.** Build only the T, T-1 (and optionally T-2) fits. If C_T fits well (high held-out R²) and the next links also fit well with stable R², the first recursion links are sound and R2/R3/R7 are unlikely to be fatal. Log, beyond R²: held-out gradient error, ensemble disagreement, the optimism gap `mean_k C_k − C_{eval}(argmax)`, off-box query frequency, and — for R1b — non-trivial gradient of C in the belief coordinate. A 1–2 day check before committing to the full horizon.

## 9. Deferred refinements and the production safety layer

These are real but **not day-one** — they presuppose the Tier-1 stack works, and adding them up front would make a 255-link failure un-attributable. Named here so they aren't rediscovered, sequenced after the basic stack passes the full-depth toy.

**Deferred refinements (Tier 3), add one at a time, each re-checked on the toy:**
- **Differential PCA / relevance compression** (paper Appx 2): rotate the state to relevance axes and drop irrelevant directions safely (it filters on relevance, not variance). On-theme for the postfix7 "unconstrained directions the max exploited" failure — but less urgent once advantage-learning, exact-accounting factoring and cash-normalization have already shrunk the *single-deal* state. Cheap to add as preprocessing once the coordinates are fixed. Its real payoff is at **book scale** (see "Book extension" below), where the union state is large and redundant — applied to the full sufficient state, never value-first.
- **Active resampling near switching surfaces**: after an initial fit, find states where the top-two action gap is small (the policy boundaries, where kinks and expensive errors live) and resample them with higher M / more ensemble heads, then refit. Spends compute where it changes the policy, not where it only improves value R².
- **Shared trunk / temporal regularization**: only if independent per-t fits prove too noisy or unstable across horizons. It reintroduces the cross-step coupling the per-t independence was built to remove, so it is a fallback, not a default. The cheap half — horizon-relative input features (§ Tier-2) — is already adopted without it.

**Production safety layer (deployment hardening, orthogonal to core validation):** reject a trade when ensemble disagreement is high or the top-two actions are within noise; reject boundary actions unless independently confirmed; cap one-day inventory jumps; fall back to the baseline hedge when the off-box/clamp rate is high; and — the key one — **fall back to baseline when the learned policy worsens an independent fresh-MC evaluation**, which is the §8 policy-evaluation metric wired in as a live circuit breaker.

**Book extension (deferred): multi-underlying under a global loss budget.** The first build is one underlying; this is the path to a book of N underlyings (platinum, gold, …) under the single global utility `U(W_T)`, `W_T = Σ_k W_T^k` (global confirmed, R8). It is coupled, but the coupling is a single scalar, so the single-underlying solver is the building block. Stated to implement unambiguously:

- **The book state is the union of per-underlying states — never the scalar portfolio value.** Each underlying keeps its own sufficient state from the single-deal design: `(belief_k, liability_k [the weighted-sum scalar], loss_budget_k, inventory_k, horizon-features_k)`. Portfolio value `W_t` is a sufficient statistic for the *objective* (U sees only `W_T`) but **not** for the *decision*: the hedge keys off *remaining risk* — how much variance is still live, and in which underlying — and value blurs that out. Two books at the same `W_t` can have opposite optimal hedges (one with deals early in their averaging windows and large remaining variance; one nearly locked). This is the single deal's own `(partial_avg, n_remaining) ≫ MTM` argument one level up. And unlike swaps *within* one underlying (which collapse to one scalar, R8), per-underlying liability scalars do **not** aggregate across underlyings — different regimes and mean-reversions — so the book state is irreducibly the union of per-underlying pieces plus inventories.
- **Portfolio value is the coupling coordinate, not a state replacement.** The rest of the book bears on underlying k only through total wealth: under `U(W_k + W_{-k})` the marginal value of a k-gain depends on rest-of-book wealth `W_{-k}`. So `W_{-k}` is exactly — and only — what underlying k needs from the rest of the book. That is what makes the decomposition work.
- **Best-response coordination (preferred), explicitly:** (1) initialize each underlying's policy by a single-underlying solve in isolation; (2) to update underlying k, re-run the single-underlying backward solver unchanged except that terminal and λ-rollout utility are evaluated as `U(W^k + W_{-k})` **per path**, where `W_{-k}` is the rest-of-book terminal wealth realized on that *same correlated scenario* under the other underlyings' current frozen policies; (3) cycle k = 1…N until policies stop changing. Sound because `W_T` is affine in the inventories and `U` is concave, so the joint objective is concave and coordinate ascent converges. Here `W_{-k}` enters the **terminal utility per path, not the state**, and the solver is re-run per outer iteration. Simulation must be joint/correlated across underlyings (existing riskflow machinery) so each path's `W_{-k}` carries the right cross-correlation (the diversification channel) and shares the loss pool (the budget channel).
- **Alternatives.** *Mean-field (one solve, approximate):* instead of re-solving, add a low-dimensional rest-of-book wealth summary (level + a dispersion measure) as an extra **state coordinate** to each `C_t^k` and solve once — cheaper, but approximate, because symlog nonlinearity makes higher moments of `W_{-k}` matter and a scalar summary loses them; use only if best-response is too slow. *Dual budget-price:* solve each underlying against a scalar price on shared-budget usage, with an outer loop setting the price to hit the global budget — equivalent at the optimum.
- **Differential PCA is the book-scale compressor — applied to the full state, never value-first.** At book scale the union state is high-dimensional with heavy cross-underlying redundancy and irrelevance, so differential PCA (paper Appx 2) earns its keep here, where it did not for the single deal (whose state is already tiny). Strict order: **full sufficient book state → differential PCA (keep high-relevance directions by differential magnitude, drop the irrelevant) → fit `C` on the compressed factors.** Note this *keeps* remaining-average / remaining-fixings — they are high-relevance (they strongly move the value), so differential PCA is the cure for the blur, not a cause of it. **Anti-pattern, do not:** reduce to portfolio value first and then "PCA" — PCA on a scalar is a no-op, and you have already destroyed the remaining-risk composition the hedge needs. Differential PCA *compresses* a sufficient state; it cannot *reconstruct* sufficiency from value.

## 10. Honest summary for the reviewer

The design is **approximate backward dynamic programming**: post-decision continuation functions fit by differential ML, with the regression target a variance-reduced one-step conditional expectation, and the Bellman max kept as an explicit, low-dimensional operator over the already-fitted surface. It reduces an unsolved recursive-DP problem to up to 255 *bootstrapped* links, each of which is now an instance of a solved problem class — smooth-payoff differential ML on a bounded domain. The links are not independent; R2 is the price of that. The strongest argument for the design: postfix2–7's pathologies were artifacts of a Bellman max applied recursively to an in-progress fit on off-hull, path-coupled states, and this design removes exactly that while preserving dynamic re-optimization.

The strongest arguments against, in order: **R1b** (the decision rule needs an observable state, but the codebase exposes the privileged true regime and has no filter — fixable with a belief filter, but unproven that the belief is discriminative enough to hedge on); **R2/R7** (up-to-255-deep compounding of fit error *and* max-bias, with kinks from the discrete decision operator concentrating that error — no published precedent at this depth with a per-link max; mitigations pre-identified but not free). R1a and R6 are now closed by the code read, and the portfolio generalization (R8) collapses to one synthetic swap rather than complicating the state.

If the belief filter makes R1b's state both observable and discriminative, and the deepened reduced-problem test tracks the exact dynamic DP (not the static-hold value) across depth, we believe this ships on a 3090 in a daily-refresh budget.

The question for the next opinion: **with advantage-learning, policy-evaluation, the LCB operator and the near-terminal high-fidelity solver in place, does the action *ranking* (not the value level) stay correct across the full 255-link toy — and does the belief filter (R1b) make the regime state both observable and discriminative enough to hedge on?**
